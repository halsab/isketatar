# Реализация курса

Начало: 12 сентября 2026 года. Основание — [D0–D12](../production/11-development-roadmap.md). Новое поручение владельца разрешает разработку и локальные коммиты; прежнее ограничение «только документация» относится к завершённому этапу проектирования. Push и публичный релиз не выполняются.

Каждый этап и выделенный подэтап выполняется последовательно: границы → необходимые проверки → реализация → независимое ревью с чистым контекстом → исправления → локальный коммит. Тесты прежде реализации применяются к предметным правилам, транзакциям и отказам; для вёрстки используются проверки браузером. Ревьювер читает спецификацию и diff самостоятельно, не получает объяснений автора реализации.

## D3.2: перенос и восстановление

Добавлены закрытые схемы записей и обменного конверта, сборочная генерация Ajv standalone, структурная проверка чтения/записи IDB, согласованный экспорт, проверка файла и предварительный просмотр, атомарная замена и reset. Импорт проверяет размер до чтения, UTF-8, глубину и опасные ключи, уникальность и внутренние связи, доступные точные revisions и политики. Stack обхода ограничен глубиной, широкий массив не создаёт отдельного кадра для каждого элемента. Лимит сырого ответа — 4096 UTF-16 units; производный NormalizedAnswer имеет отдельный запас для NFC (16384 units на строку, 4097 частей).

Завершённые оценки с доступными grading/normalization перепроверяются; изменение одной политики поиска не уничтожает их. Неизвестная revision/политика и зависимые записи сохраняются в legacy. Актуальный сеанс не может ссылаться на предъявление только из legacy. Закреплённый, но недоступный незавершённый выпуск сохраняется историей; совместимый active импортируется как paused. Импорт и reset создают новые generation/epoch; прежние callbacks и изменившийся preview отвергаются. Отказ после очистки stores откатывает всю транзакцию, предыдущий набор остаётся целым. Время ручного добавления/suspend не угадывается из часов: статистика SRS проверяется на поддержку первыми ответами, включая последний учтённый Attempt.

D3.2 создаёт первый поддерживаемый обменный формат; D3.1 был локальным промежуточным кодом без экспорта и без подключённого интерфейса прогресса, публичных файлов/миграций этого подэтапа нет. Снимок Attempt теперь включает фактическую помощь строки до отправки, поэтому помощь последующего retry не меняет прежний результат при переносе. Физическая БД и progress schema первого выпуска имеют версию 1; более новые неподдерживаемые версии отклоняются без удаления БД.

Независимое ревью исправило пустой импортированный set, смешение current/legacy ссылок, UTF-16 и расширение NFC, поддержку счётчиков SRS и совместимость политик. Целевой независимый прогон: 51 тест в четырёх файлах; допуск дан без открытых существенных замечаний. Браузерный harness подтвердил десять инвариантов, включая перенос и reset; Playwright — 2/2. TypeScript, исходные валидаторы, границы модулей и production build проходят. Следующий подэтап D3.3 — отдельная несохранённая ветвь памяти и её ограничения.

## D3.3: несохранённая ветвь памяти

Добавлен атомарный MemoryBackend с теми же проверками записей и команд. Явное переключение создаёт отдельную generation и приостанавливает скопированные сеансы; исходный репозиторий перестаёт принимать учебные записи. При недоступном снимке можно начать пустую ветвь. Экспорт сохраняет её в стандартном формате; импорт и очистка памяти не меняют исходную БД. Мягкий durable-предел не мешает временной работе, жёсткий предел переносимого файла сохраняется.

Известная незавершённая диагностика/итог в исходной БД защищает раскрытие помощи и после переключения, импорта или очистки памяти. Флаг сначала фиксируется в исходной БД; при невозможности записи раскрытие откатывается. Закрытое соединение открывается временно только для этой операции. Снять защиту после сброса можно по подтверждённой новой generation реального durable-reset, а не по одному флагу интерфейса.

Независимый ревьювер с чистым контекстом обнаружил потерю защиты при импорте проверки и закрытии до следующего snapshot. Исправление обновляет известную защиту после успешного commitImport; регрессия закреплена. Повторное независимое ревью: 55/55 целевых тестов, существенных открытых замечаний нет. Полный check: 140/140, TypeScript и исходные валидаторы проходят. Реальный Chromium подтвердил 12 инвариантов хранилища, включая durable-защиту и изоляцию памяти; Playwright — 2/2, production build проходит. D3 завершён; интерфейс переключения подключается в следующих этапах.

## D8.3a: транзакционная блокировка обновления

ProgressRepository предоставляет begin/commit/cancel/finish/recover для update_gate. Все переходы выполняются атомарно с CAS generation/epoch/state_revision; begin/commit/cancel требуют действующего coordinator/writer. Commit требует отсутствия active-сеанса и замораживает все пользовательские команды. Finish требует reader целевого выпуска. Отмена допустима только доcommit; recovery требует явного подтверждения, меняет epoch/coordinator и сохраняет ID/фазу операции. Ни время, ни takeover не снимают блокировку автоматически.

Expected.update_id фиксирует допуск наблюдения до появления gate: quiescing завершает уже допущенную монотонную запись, но отвергает новое раскрытие. Draft/pause/position владельца остаются разрешены для согласованной остановки. Receipt отражает текущий gate и не получает прежний допуск повторно. Защита durable-источника memory-ветви также учитывает gate. Технические поля не попадают в export и не меняют историю ответов.
