# Приёмка реализации

Отчёт отделяет автоматизированную инженерную проверку от внешней приёмки. Конкретные builds, команды и итоги этапов записываются ниже. Проверки после изменения затронутого кода повторяются; старый отчёт не разрешает публикацию нового SHA.

## D9.1 — движки и полный корпус

Playwright1.63.0: Chromium153.0.8010.12, Firefox155.0, WebKit26.6; macOS на arm64, Node24.21.0. WebKit — тестовый движок, не физический iPhone и не установленный Safari. Все общие сценарии выполняются в каждом движке, retries=0. Шесть сценариев прямой инъекции отказа в worker выполняются только в Chromium: API [serviceWorkers](https://playwright.dev/docs/api/class-browsercontext#browser-context-service-workers) отсутствует в других движках. Полный корпус выполняется один раз в Chromium; основные учебные механики и все четыре answer controls проверяются во всех трёх.

Полный проход читает реальные страницы всех уроков, отправляет авторские ключи всех вопросов, проверяет feedback/acknowledgement и20 итоговых заданий с закрытым до submit разбором. Он подтверждает проводку UI и сохранение494 Attempts/65 завершённых Session после смены пути и reload. Лингвистическая правильность ключей этим способом не подтверждается.

Офлайн проверяется отключением HTTP у изолированного тестового сервера: каждый запрос, в том числе от worker, завершается обрывом соединения, готовый ответ не подменяется фикстурой. После смены режима повторно проверяется и ответ уже начавшегося чтения файла. Первоначальный прогон обнаружил ограничения Playwright setOffline: Firefox отвергает fetch с cache=no-store, WebKit — navigation даже с активным worker. Это воспроизведено отдельно минимальным worker, всегда возвращающим синтетический HTML, без кода курса. При обрыве HTTP тот же worker обслуживает оба запроса. Серверный метод проверяет отсутствие сети, но не системный индикатор navigator.onLine или авиарежим устройства.

## D9.3a — измеритель, размерные бюджеты и загрузка

`npm run build` создаёт проверяемый граф JS/CSS и выполняет `check:budgets`. Граф привязан к хешам именно собранных chunks. Общие зависимости учитываются один раз; сумма всех JS с worker даёт консервативную верхнюю границу любого маршрута. Полный пакет включает также тела transport и release manifest. Размерный контракт уточнён явно:180KiB для renderer и200KiB вместе с обязательным worker; прежний общий180KiB не объявляется выполненным.

Начальная загрузка отделена от React render: небольшой bootstrap предварительно загружает данные, валидаторы и код выбранного маршрута; hash, схема и разрешение показа остаются в штатном пути. Начальный runtime запускается один раз; кнопка retry сохраняет отдельное действие. Команды и импорт/экспорт загружают тяжёлую реализацию по требованию до открытия IDB-транзакции; после загрузки повторно проверяются закрытие и отделение репозитория. Повторяющиеся primitives/nullable/policy в standalone schemas используют общие определения, а worker проверяет точный Control вместо Meta union.

В шрифтах оставлены все знаки корпуса и дополнительные базовые диапазоны. Noto42 944байта, Inter99 840байт, вместе142 784 вместо452 468. Сохранён исходный variable range Inter100–900: эксперимент с его сужением дал различие при600 и исключён. Итоговый shaping совпадает с исходниками на1200 арабских runs и8978 кириллических/латинских runs при400/500/600/700, включая glyph mapping, clusters, advances и offsets. Проверенные hashes и инструменты — font-build.json. Лицензии оригиналов сохраняются.

Все обязательные startup chunks, UpdateStatus и CSS входят в shell cache, даже если main импортируется динамически. Один список boot modules используется сборкой и проверкой бюджета. Заголовок manifest и канонически отсортированные shell paths входят в release fingerprint; изменение состава оболочки не переиспользует старую immutable identity. Браузерный regression открывает главную в новом окне без сети после удаления полного курса и проверяет его CSS.

## D9.3b — холодный запуск

Runtime запускается параллельно renderer через общий Promise; начальное событие установки перехватывается до обоих. HTML hints включают обязательный JS/CSS, а bootstrap загружает выбранную страницу и её отдельный standalone validator. Все ленивые страницы начальной оболочки входят в shell cache и размерный бюджет. Схемы не ослаблены; Ajv использует общие определения и циклы для required/enum.

Ранняя регистрация worker делится с runtime. Предварительный запрос manifest не пишет CacheStorage/IDB и не принимает выпуск: worker хранит один ограниченный результат обычного fetchManifest с проверкой размера, MIME, URL, JSON и структуры. Страница получает результат по созданному ею MessagePort и повторяет parseRelease, версии, policies, content-index и принадлежность собственному immutable URL. Клиент не передаёт worker готовый manifest. Если подтверждение новой команды ещё не пришло, bootstrap сразу использует обычный fetch; отказ после подтверждения также включает обычный запрос. Повторный старт после отказа активации заново регистрирует transport; поздний отказ старого waiter не сбрасывает новый Promise.

Initialize возвращает проверенную роль выпуска до автоматического сохранения shell. Запись shell остаётся в сериализованной очереди worker перед обновлением/удалением и удерживается event.waitUntil. Ошибка фоновой записи видна в состоянии PWA и не закрывает уже работающую онлайн-страницу; полный курс не становится ready. Ресурсы сохраняются порциями по четыре: отказ ожидает уже начатые записи и не запускает следующую порцию.

502 видимые словарные записи и282 учебных вхождения теперь передаются раздельно. Первый свободный поиск не скачивает vocabulary; доступ к учебным вхождениям по-прежнему определяется экспозициями/ответами. Загрузчик сохраняет прежнее агрегирующее имя dictionary.json и отдельный адаптер для retained выпусков с единым файлом. Оба новых ресурса обязательны в manifest и полном офлайн-пакете. Форма поиска остаётся смонтированной при догрузке: ввод и фокус сохраняются, устаревшие ответы игнорируются, индекс обновляется после загрузки. Счётчик появляется после данных; сами группы остаются за font/Disclosure gates. Заголовок урока берётся из проверенного core до загрузки документа; прежняя граница SessionContent сохранена.
