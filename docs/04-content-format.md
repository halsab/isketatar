# Формат учебных данных

## Общие правила

Все файлы — UTF-8 JSON. Поля `*_tt` предназначены для ученика и содержат татарский текст; арабографические примеры являются допустимыми вставками. Остальные поля служат связям, проверке и редактуре. Не выводить весь объект автоматически в пользовательский интерфейс.

ID устойчивы между редакциями. `source_sections` ссылается на `sources/sections.json`; `source_lines: [a,b]` — включительный диапазон строк `sources/textbook.txt`, нумерация с 1, разделитель только LF. U+2028 внутри строки не меняет её номер. Исходная форма хранится буквально; display-форма и чтение могут быть отредактированы с явно указанным основанием.

Профили: `book_jadid_10`, `book_jadid_6`, `book_kadimi`, `book_yanga`, `loan_original`, `book_unspecified`. Точные значения и ограничения — в редакционной политике. `book_unspecified` означает конкретное написание книги без уверенного отнесения всей формы к единой системе; это не универсальная норма.

## Карта программы

`curriculum.json`: `version`, `language`, `default_profile`, массив `modules`, объект `routes`, массив `lessons`. Модуль содержит ID, татарское название, маршрутный тип и упорядоченные `lesson_ids`. Каждый маршрут — упорядоченный массив ID уроков. Метаданные урока: `id`, `module_id`, `title_tt`, `route`, `prerequisites`, `source_sections`, `required_for_completion`, `skills`.

`skills.json`: записи `id`, `lesson_id`, `target_tt`, `source_sections`, `evidence`, `facets`. Один итоговый навык связан с уроком; внутри его заданий отдельно различаются графика, чтение, правило и морфология. `source-coverage.json` содержит назначения всех разделов источника. Один раздел может участвовать в нескольких уроках.

## Полный урок

Файлы `content/lessons/M*.json`: `module_id`, `title_tt`, `lessons`.

| Поле урока | Смысл |
|---|---|
| `id`, `title_tt`, `prerequisites`, `source_sections` | Совпадают с программой. |
| `goals_tt` | Краткие цели, массив строк. |
| `theory_tt` | Полные абзацы теории; порядок сохраняется. |
| `rules` | Объекты `id`, `statement_tt`, `scope_tt`, `source_sections`. |
| `examples` | Подготовленные разборы с источником и ролью. |
| `pitfalls_tt` | Типичные ошибки и ограничения. |
| `outcomes_tt` | Что ученик умеет после урока. |

У примера обязательны `id`, `source_form`, `display_form`, `reading_tt`, `meaning_tt`, `explanation_tt`, `source_lines`, `profile`, `status`, `normalization_note`, `usage`. Чтение может быть `null`, когда пример учит узнавать конструкцию, а полное татарское чтение не подтверждено. Это не разрешает делать из него открытый вопрос на чтение. Значение может объяснять конструкцию или категорию имени вместо неподтверждённого перевода имени.

`usage: demonstration` — показать в теории; `assessment_source` — источник закрытого задания. Наличие второго типа в том же JSON не означает, что его следует выводить в теоретической части. Правила из уроков индексируются в `content/reference/rules-index.json`; индекс хранит ссылки, а не отдельную конкурирующую формулировку.

## Задания

Файлы `content/exercises/M*.json`: `module_id`, `items`. Каждый вопрос содержит:

- `id`, `lesson_id`, `rule_ids`: адрес и учебная связь;
- `type`, `prompt_tt`, `stimulus`: вид вопроса, инструкция и изучаемый текст;
- `options`: массив `{id,text_tt}`, пустой для открытого ввода;
- `accepted_answers`: список явно допустимых ключей;
- `explanation_tt`, `hints_tt`: объяснение и ступени помощи;
- `source_example_ids`, `source_lines`, `profile`: происхождение;
- `skill`: `letter`, `reading`, `rule` или `morphology`;
- `difficulty`: 1–3, относительная сложность внутри курса;
- `assessment_role`: `practice` или `transfer`;
- `grading`: `exact_option`, `set`, `tt_reading` или `segments`.

`choice/exact_option` принимает один ID. `select_many/set` принимает весь набор ID независимо от порядка. `reading/tt_reading` принимает любой из явно заданных текстовых вариантов. `segment/segments` принимает один из вариантов разбиения: части записаны кириллицей через `+`. Пробелы вокруг `+` несущественны; каждая часть нормализуется как татарский ответ. Порядок частей и их буквы значимы. Вопрос говорит, нужно ли отделить одну последнюю морфему или разделить слова, поэтому разные уровни морфемного анализа не превращаются в скрытую неоднозначность.

Опции могут содержать неправильные написания как отвлекающие варианты. Их наличие не означает, что эти формы допустимы в словаре или в теории. Правильность определяется только ключом конкретного вопроса. `hints_tt` не показывается до запроса помощи; `explanation_tt` — до ответа.

## Диагностика и итог

`content/assessment/diagnostic.json` и `final.json` имеют собственные `items`. Вместо привязки к одному уроку они содержат `recommend_lessons`, `group`, собственные `source_form/source_lines`. Общие поля проверки совпадают с обычными заданиями. Диагностический банк не участвует в обязательном числе заданий уроков.

`final.json` дополнительно ссылается на два текста и четыре вопроса из `content/readings/questions.json`. Они добавляются в итоговый сеанс после 16 основных вопросов. Не копировать их в другой файл с теми же ID. Рубрика и назначение групп описаны в `docs/05-assessment.md`.

## Словарь и тексты

Исходниковый словарь и поиск подробно описаны в `docs/06-lexicon.md`. Полный корпус содержит 540 записей с `eligibility`, а активная лексика примеров курса — в `content/lexicon/course-vocabulary.json`. Последняя ссылается на конкретные примеры и словарные совпадения; она не заменяет исходниковый корпус и не должна удваивать одинаковое слово в выдаче.

Тексты, строки, словарные подсказки и вопросы чтения описаны в `docs/07-reading-media.md`. `reading_status: editorial_checked` отличает редакторское чтение строки по правилам книги от прямо напечатанной в книге транскрипции. Составленная подборка исходных предложений не выдаётся за цельный исторический документ.

## Проверяемость

`tools/validate_content.py` проверяет целостность корпуса: исходный хеш, адреса, маршруты, покрытие, ID, обязательные поля, ссылки, наличие ключей, роли примеров и допуски словаря. `--partial` служит работе над незавершёнными модулями; для итоговой проверки флаг не используется. Скрипт не проверяет автоматически истинность лингвистического утверждения или естественность татарского языка. Содержательные решения и реальные границы проверки фиксируются отдельно в итоговом аудите.
