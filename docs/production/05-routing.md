# Маршруты, история и прямые ссылки

Статус: контракт будущей реализации, без кода приложения. Владение состоянием задано [архитектурой](01-architecture.md), записи Session и ResumePosition — [контрактами данных](02-data-contracts.md), доступ к материалам — [учебной механикой](03-learning-mechanics.md). Этот документ определяет адреса и переходы; компоновку экранов уточняет [спецификация экранов](06-screen-specs.md), поведение фокуса — этап 07. Все пользовательские названия и сообщения — по-татарски.

## 1. Адрес приложения

Базовый путь GitHub Pages — `/isketatar/`, маршрутизатор — HashRouter. Полный адрес урока имеет вид `https://<owner>.github.io/isketatar/#/lessons/V04`. Сервер получает `/isketatar/`; путь после `#` разбирает приложение. Поэтому обновление страницы и открытие ссылки не требуют серверного перенаправления каждого урока. Отдельного маршрута `/isketatar/lessons/V04` нет. Произвольные чистые пути не переписываются универсальной страницей 404.

Vite base, адрес манифеста, start_url, область service worker и пути ресурсов согласуются с `/isketatar/`. Ни один переход приложения не формируется как `/assets/...` или `/#/...` относительно корня владельца. Пустой hash заменяется на `#/` без добавления записи истории. `/isketatar` нормализуется к базовому пути средствами хостинга; приложение не обещает загрузку при неправильном домене или отсутствии shell.

Query принадлежит hash: `#/dictionary?q=галим&scope=all&expanded=0`. Значения кодируются штатным URL-кодированием. Внутренний якорь передаётся через `at`, поскольку второй hash не является независимым адресом прокрутки. Ссылки — обычные ссылки, поддерживающие копирование и открытие в новой вкладке.

## 3. Параметры и проверка URL

| Параметр | Допустимое значение и источник |
|---|---|
| `lesson_id` | Существующий ContentId из curriculum и lessons, например `V04`; регистр значим |
| `reading_id` | ID из readings/texts: `READ-01`…`READ-10`, `READ-F01`, `READ-F02`; наличие не отменяет ограничения доступа |
| `entry_id`, query `entry` | Точный ID lexicon либо course_vocabulary, например `lex-55-046`, `COURSE-EX-B07-01`; архив и закрытые вхождения проверяются до показа |
| `letter_id` | Реальные `LETTER-01`…`LETTER-34`; `LETTER-01` — Әлиф. Лигатуре и marks не присваиваются выдуманные буквенные IDs |
| `rule_id`, query `rule` | Существующий `R-*` из rules-index и уроков |
| `profile_id` | Один из шести IDs profiles.json, включая `book_jadid_10`, `book_jadid_6`, `book_yanga` |
| `term_id` | Существующий `TERM-*` из terms.json |
| `session_id` | LocalId UUID; поиск только в локальном снимке пользователя, затем проверка kind, цели, status и совместимости |
| `q` | Только `/dictionary`; поисковый текст до 256 кодовых точек, пустое значение по умолчанию |
| `scope` | Только `/dictionary`: `all` по умолчанию либо `saved`; saved фильтрует закладки этого устройства |
| `expanded` | Только `/dictionary`: `0` по умолчанию — обычный поиск, `1` — явный расширенный поиск с вариантами yeh/kaf по политике поиска; не открывает недоступную лексику |
| `at` | Существующий смысловой блок именно текущей страницы; не CSS-селектор и не номер пикселя |
| `panel` | Ровно одно значение: `word`, `entry`, `rule`, `source` |
| `word` | Вычисленный word_id текущего текста, например `READ-01-L01:0`; ordinal начинается с 0 |
| `source_id`, query `source` | Существующий ID из sources/sections.json, например `S-015`; порядок и номер раздела не выводятся из суффикса ID |
| `context` | Только `/sources/:source_id`: точный ID доступного EX-примера, lex-статьи, строки `READ-01-L01` либо RQ-вопроса; связь с разделом проверяется по источниковым LF-адресам |

Каждому panel соответствует ровно один одноимённый целевой ключ. Остальные целевые ключи удаляются. Повторённые управляющие query-параметры считаются некорректными: панель не открывается, конфликтующая группа очищается через replace. Неизвестные query не исполняются и удаляются; неизвестный путь или ContentId показывает ошибку адреса, сохраняя понятный переход в каталог. Некорректная percent-последовательность не обрушает shell. IDs декодируются один раз, не приводятся к нижнему регистру и не превращаются в путь файла.

При отсутствии необязательных query действует значение по умолчанию; канонический сериализатор опускает пустой q, scope=all и expanded=0. Группировка дочерних source IDs сохраняется в обоих режимах поиска; локальное раскрытие группы не записывается в URL. Слишком длинный поиск сообщает ограничение и не запускается с незаметно обрезанным запросом. Импорт, оценки, ответы, черновики, writer-токены и настройки не читаются из URL.

## 4. Начало и восстановление сеанса

Открытие учебного адреса, prefetch, повторный render и reload не создают Session. Без подходящего сеанса показывается введение с явным «Башларга». При наличии paused предлагается «Дәвам итәргә»; restart отдельно подтверждает отказ от старого черновика. Команда начала проверяет полный план, закреплённый пакет и возможность записи, сохраняет сеанс и только затем открывает первый вопрос. Для диагностики и итога адрес остаётся прежним.

Уже active сеанс той же вкладки восстанавливает сохранённый вопрос без нового начала. Paused требует явного resume. Перед переходом к другому упражнению прежний active становится paused с черновиком; более одного active и двух незавершённых сеансов одной цели не возникает. Панель внутри задания не приостанавливает его. Выход на полную страницу сохраняет и приостанавливает сеанс. Обычный Back не отправляет ответ, не выполняет acknowledgement и не завершает упражнение.

Адрес результата проверяет не только UUID: lesson_id/reading_id должны совпасть с целью сеанса, а kind — с семейством страницы. Для active/paused по адресу result показывается предложение продолжить без разбора; для abandoned/incompatible — состояние сохранённой истории с объяснением и безопасным новым началом. Отсутствующий UUID не заменяется «последним результатом». Результаты доступны лишь в этом локальном наборе данных либо после совместимого импорта.

## 5. История переходов

Приложение помечает собственные записи history.state техническим navigation key, предыдущим ключом и сведениями возврата. Это краткоживущая навигация, не источник прав записи или прогресса. Не использовать history.length или referrer как доказательство безопасного Back. В состоянии истории нет копий ответов.

| Действие | Операция и следствие |
|---|---|
| Переход в другой раздел или конкретный материал | push; предыдущая страница и её позиция доступны Back |
| Повторный выбор текущего основного пункта | Нет новой записи; список открывается только отдельным переходом |
| Явный переход по оглавлению к `at` | push; Back возвращает предыдущий блок |
| Обычная прокрутка или смена размера текста | Без изменения URL; обновляется ResumePosition |
| Первое открытие контекстной панели | push поверх текущей страницы |
| Другое слово при уже открытой панели | replace текущей панели; одно закрытие возвращает к странице |
| Закрытие панели | back только при подтверждённой собственной предыдущей записи основы; иначе replace URL без panel/целей |
| Связанный подробный материал из панели | push полной страницы; Back восстанавливает панель |
| Набор поиска | replace после 250 ms без ввода; новый history item на каждую букву не создаётся |
| Отправка формы поиска | Завершает debounce; push только при действительно новом запросе, иначе без дубликата |
| Очистка непустого поиска, изменение scope/expanded | push нового состояния; Back возвращает предыдущую выдачу |
| Submit вопроса / следующий вопрос | Команда сеанса без нового адреса вопроса |
| Завершение всего сеанса | После commit replace учебного адреса на result; review сохраняет свой адрес. Back не открывает устаревший экран отправки |
| Исправление формата URL, завершение onboarding-перехода | replace; технические промежуточные страницы не размножаются |
| Системный Back/Forward | Восстановление записи с повторной проверкой доступа; не повтор команды start/submit |

Debounce отменяется при уходе со страницы, чтобы старый поиск не переписал следующий адрес. Переход к статье из выдачи — push: Back возвращает query, фильтр и позицию списка. При неизвестном предшественнике внутренняя кнопка «Назад» ведёт в логический родительский каталог через replace, а браузерная кнопка сохраняет обычную семантику браузера.

## 6. Единственная контекстная панель

Пример: `#/reading/READ-01?panel=word&word=READ-01-L01%3A0`. Основная страница остаётся владельцем панели. `word` разрешается только в строках текста данной страницы или разрешённого текстового контекста текущего задания; совпадения написания недостаточно. Для примеров урока используются связи на entry/rule, а не искусственный word_id.

Источник `panel=source&source=S-015` показывает название раздела. Если основной блок, слово или предъявление имеет точную связь с ним, карточка добавляет соответствующий source_form и LF-диапазон; `at=EX-ID` уточняет пример урока. Без однозначной связи остаётся карточка раздела. Полный DOC или учебник офлайн не обещается. Исходниковая карточка не раскрывает скрытый ответ.

Полная страница `/sources/:source_id?context=...` проверяет доступность контекста и принадлежность каждого показываемого LF-адреса разделу. Для RQ используются связанные строки, для COURSE — source_example_id. Источник из word-панели открывается полной страницей с context=line_id; Back возвращает панель. Отсутствующий или чужой context даёт сообщение без фрагмента; без context показаны только сведения об учебнике и разделе. Query не разрешает загрузку произвольного файла.

Открытие нового уровня помощи сначала фиксируется по механике обучения. Query не может обойти этот шаг. При несохранённой диагностике/итоге переход к учебной помощи сначала показывает предупреждение о переходе проверки в учебный режим; материал отсутствует в доступном DOM до подтверждения и записи события. Отмена не раскрывает данные. Недоступные встроенные панели во время проверки не возникают даже по вручную набранному URL.

Вложенных панелей и модальных диалогов нет. Ссылка «полная статья» из word-панели открывает `/dictionary/:entry_id`, правило — `/reference/rules/:rule_id`. Возврат сохраняет предыдущую панель, строку и уже раскрытые уровни помощи. Forward после закрытия собственной панели вновь открывает её, проверяя актуальные права доступа. Прямой вход с panel без собственной основы закрывается через replace и не выбрасывает человека на внешний сайт.

Для этапа 07 передаются trigger identity, основной anchor, положение внутренней прокрутки панели и причина закрытия. Узкая панель блокирует фон и его прокрутку; широкая соседняя колонка немодальна. Блокировка и фокус относятся к текущему слою, а не к самому URL. При полном переходе блокировка снимается, фокус получает заголовок новой страницы. При возврате восстанавливаются панель и её контроль; после закрытия — исходное слово/кнопка, а если их уже нет, заголовок основного блока. Resize не добавляет историю и не теряет адрес панели.

## 7. Смысловая позиция

Индекс якорей строится из текущего каталога: line_id для чтения, R-ID и EX-ID для правил и примеров, LETTER-ID для таблицы букв. У уроков дополнительно определены разделы `{lesson_id}:goals`, `:theory`, `:pitfalls`, `:outcomes`; у `/reference` — `rules`, `profiles`, `terms`, `letters`. Это адреса UI-блоков, не новые предметные IDs. У абзацев theory_tt пока нет собственных редакционных IDs: не обещать устойчивость адреса вида `theory:3` при перестановке массива.

Приоритет восстановления: валидный явный `at`, затем позиция соответствующей записи Back/Forward, затем ResumePosition при обычном возврате к материалу, затем начало. Прямой `at` ставит начало блока; after-layout поправка учитывает закреплённую шапку. Сохранение использует kind, target_id, anchor_id, within_block_ratio, content_revision, updated_at из 02. После смены шрифта повторно находится смысловой блок, а не прежний scrollY.

При изменённой ревизии существующий устойчивый anchor сохраняется, исчезнувший заменяется началом материала; ordinal старого слова не переносится молча. Якорь не раскрывает закрытый блок. Позиция не является закладкой или отметкой завершения. Ввод и выбор ответа восстанавливаются исключительно из Presentation, никогда из позиции прокрутки.

## 8. Прямой вход, ошибки и доступность

Сначала разбирается адрес, затем готовность shell/хранилища/каталога, существование IDs, локальный доступ и состояние сеанса. Только после этого материал раскрывается. Отсутствие файла офлайн — content_unavailable, а не «несуществующий урок»: URL сохраняется, доступны повтор загрузки и возврат к сохранённым материалам. Частичный пакет не выдаётся за полный; новый итог нельзя начать без всех 20 вопросов. Недоступность арабского шрифта блокирует оцениваемый стимул, сохраняя черновик и возможность читать кириллическую теорию.

Незавершённый onboarding не закрывает теорию, словарь и справочник. Если команда учебного начала требует выбрать путь, переход на `/start` сохраняет проверенное внутреннее намерение в history.state; завершение возвращает его через replace и предлагает начало/продолжение. Произвольный внешний returnUrl не принимается. Диагностика допускает ещё не выбранный маршрут. Reload страницы выбора сохраняет намерение из её history.state; при его отсутствии следующий экран — первый урок выбранного пути.

READ-F01/F02 показываются как разбор после первой submitted итоговой попытки. До этого прямая ссылка показывает объяснение и переход к `/final`, без чтения, значения или словарного обхода. `/reading/:final_id/questions` не создаёт reading_practice: предлагает существующий итоговый результат либо начало проверки. Учебные COURSE-вхождения подчиняются with_lesson/after_linked_question; закрытая запись не раскрывается query-панелью.

Переходы ожидают текущую запись черновика. Ошибка записи даёт явный выбор восстановления или работы в памяти с предупреждением, а не фиктивное «сохранено». Сохранность не зависит от успешного unload. После импорта или передачи права записи вкладка перечитывает состояние; старый адрес не получает прежние полномочия. Маршруты настроек и экспорта доступны при восстановимом сбое курса.

## 9. Публичная ссылка

«Сылтаманы күчерергә» собирает адрес из разрешённого каталога заново: базовый путь, страница материала и при необходимости проверенный at. Не копирует location.href целиком. Панель слова превращается в ссылку на текст с at=line_id; статья и правило — в свои полные страницы. Локальные session_id, q, saved-фильтр, состояние панели и история поиска исключаются. Для результата предлагается только явно названная ссылка на соответствующий урок/текст либо раздел проверки, без обещания перенести результат. Доступ к закрытому материалу на другом устройстве проверяется заново.

## 10. Приёмочные переходы

1. Открыть `/isketatar/#/lessons/V04` в новой вкладке и обновить: тот же урок, без 404 и автоматически созданного сеанса.
2. Из прямой практики пройти выбор маршрута: возврат к исходному lesson_id; явный старт создаёт ровно один Session.
3. Начать урок, ввести ответ, уйти в другой раздел и вернуться: черновик и порядок опций сохранены, paused возобновляется явно.
4. Открыть слово, закрыть панель и нажать Forward: та же панель возвращается; прямая panel-ссылка закрывается без ухода с сайта.
5. Из word-панели открыть статью, затем Back: восстановлены слово, панель, позиция текста и фокус; вложенного диалога нет.
6. Ввести поиск, поменять фильтр, открыть статью и вернуться: выдача восстановлена, история не содержит отдельной записи каждой буквы.
7. Изменить размер арабицы и вернуться по закладке строки: смысловая позиция сохранена; исчезнувший якорь новой ревизии безопасно сбрасывается.
8. Открыть неизвестный ID, отсутствующий офлайн ресурс и чужой result UUID: три различимых состояния без выдуманного результата и потери URL.
9. Открыть READ-F01 и закрытое COURSE-вхождение до допуска, затем после допустимого события: URL не обходит раскрытие; новая итоговая попытка снова скрывает помощь.
10. Завершить сеанс и скопировать публичную ссылку: Back не повторяет submit, ссылка не содержит UUID или ответов; на другом устройстве открывается материал.
