# План производственной документации

Статус: все этапы документации 0–8 завершены; результаты и границы проверки — в [итоговой приёмке](12-completion-audit.md). Дата базовой версии: 12 сентября 2026 года. Цель — комплект однозначных спецификаций для разработки адаптивной PWA на GitHub Pages. Реализация приложения, установка зависимостей приложения, запись аудио, публикация и пользовательские испытания в текущую работу не входят.

## Иерархия документов

1. Явные указания владельца и [PRODUCT.md](../../PRODUCT.md) задают границы продукта.
2. Редакционная политика, исходные JSON и решения по источникам задают предметное содержание. Документы приложения не «исправляют» историческую графику автоматически.
3. Этот каталог — каноническая подробная спецификация **будущего приложения**. Он уточняет краткий [контракт](../08-app-contract.md); при расхождении поведения действует адресное новое решение, указанное в соответствующем документе.
4. [DESIGN.md](../../DESIGN.md) — краткая точка входа в визуальные правила; значения в design-tokens.json каноничны для токенов.
5. Результаты прежней проверки учебного комплекта остаются историческим отчётом о содержании. Новый отчёт не выдаёт план за реализованное приложение.

Текст интерфейса в спецификациях — по-татарски. При реализации новые строки переносятся в единый каталог; русские пояснения разработчика не попадают в сборку.

## Исходная база и допущения

- Базовый коммит учебного комплекта: `c821f84`; content version `2026.09.11.1`.
- Обязательный текстовый пакет: 31 JSON-ресурс, 2 131 151 байт по манифесту; это не размер приложения с кодом и шрифтами.
- Полноценный первый выпуск включает весь подготовленный корпус. Вертикальный срез в плане разработки — промежуточная проверка, не сокращённая замена курса.
- На 12 сентября 2026 года проверяются официальные документы платформ. Наличие возможности в спецификации не заменяет проверку на реальном устройстве при выпуске.
- Права на распространение, научная рецензия и пилот — внешние условия выпуска с назначаемым владельцем; научные и юридические выводы не изобретаются.
- Нет макета, обязательной палитры или выбранного владельцем шрифта. Дизайн выбирается под чтение исторической графики и обозначается проектным решением.

## Проверка документации

Проверяются относительные ссылки, JSON, соответствие реальных ID примерам, покрытие требований, согласованность алгоритмов и данных, контраст палитры, доступная проверка покрытия шрифтов и реальные ограничения платформ. Будущие проверки рендера, установки, VoiceOver/TalkBack и CI описываются как ещё не выполненные. Проверочный код для документации и содержания допустим; код приложения не создаётся.
