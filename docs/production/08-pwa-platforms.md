# PWA: установка, офлайн и обновления

Контракт будущей реализации на GitHub Pages. Проверка официальной документации: 12 сентября 2026 года. Матрица ниже описывает возможности платформ; она не означает, что готовое приложение уже испытано на устройствах. Состав данных определён в [02](02-data-contracts.md), адреса — в [05](05-routing.md), сохранность прогресса — в [09](09-security-reliability.md). Ограничения браузеров отличены от принятых здесь продуктовых решений.

## 1. Браузер остаётся основным способом работы

Курс, упражнения и словарь работают в обычной вкладке. Установка, постоянное хранилище и загрузка офлайн-пакета — три независимых действия. Ни отсутствие install prompt, ни отказ persist не закрывают обучение. Если service worker недоступен, остаётся онлайн-режим; при недоступной IndexedDB — режим памяти с предупреждением и экспортом.

Матрица обязательной будущей приёмки включает актуальную и предыдущую стабильные основные версии Safari, Chrome, Edge и Firefox (настольный браузерный режим) на перечисленных системах. На iOS/iPadOS отдельно проверяются текущая и предыдущая основные версии системы; точные номера тестируемых сборок фиксируются в отчёте выпуска. Числа Safari 17/macOS 14 в таблице обозначают начало доступности Add to Dock, а не обещание тестирования всех последующих устаревших версий. Возможность API определяется реальной операцией. Из этой матрицы не выводится обещание поддержки любого старого WebView.

| Среда | Установка и действие приложения | Данные и обязательная проверка |

Возможности остальных сред описаны в [Chrome Android](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en), [Microsoft Edge](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/ux) и [политике установки Edge](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/webappinstallbyuserenabled).

Отмена не запускает новый prompt автоматически. Определение display-mode говорит о текущем окне, а не надёжно перечисляет все установки устройства. Ручной выбор инструкции сохраняется. ## 2. Адреса и поставка

| Ресурс | Контракт |
|---|---|
| Origin и base_path | `https://<owner>.github.io`, `/isketatar/`; production использует HTTPS |
| Публичная навигация | `/isketatar/#/...`; сервер не разбирает часть после hash |
| Web app manifest | `/isketatar/manifest.webmanifest`; id и scope `/isketatar/`, start_url `/isketatar/`, display=standalone, lang=tt-Cyrl |
| Service worker | Стабильный `/isketatar/sw.js`, scope `/isketatar/`; обновление не меняет имя worker |
| Неизменяемый выпуск | `/isketatar/releases/<release_id>/…`: HTML выпуска, JS, CSS, шрифты, runtime JSON и release manifest |
| Начальный HTML | `/isketatar/index.html` — вход нового посетителя; его ресурсы указывают на один конкретный release |

Все URL ресурсов находятся внутри base_path и allowlist выпуска. Сохранённый HTML конкретного выпуска обслуживает базовую навигацию через worker; ресурсы старого клиента запрашиваются по его неизменяемым URL, а не по псевдониму «latest». Ошибка отсутствующего JSON не подменяется HTML оболочки. SPA-fallback применяется только к разрешённой навигации внутри приложения.

Для manifest нужны название, короткое название, theme/background colors и собственные подходящие icons; обычные PNG 192×192 и 512×512, отдельный maskable PNG 512×512 с важной графикой в безопасной центральной зоне. Варианты проверяются на обрезание. Apple touch icon PNG 180×180 задаётся явно. Иконка строится из простого контура открытой книги и цветов primary/on_primary, без мелких арабских надписей; её финальный рисунок проходит D4. Меняющийся номер выпуска или hash-маршрут не входит в id. Включаются Enforce HTTPS и проверка всех путей под реальным подпутём Pages. [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https), [manifest id](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/id), [SW scope](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/register).

Смена домена меняет origin: прежняя база не переезжает автоматически. Проекты одного владельца под разными подпутями имеют общий origin; имена с префиксом isketatar предотвращают случайные коллизии, но не создают границу безопасности. Нельзя удалять чужие кэши или обещать изоляцию от кода соседнего проекта. [Несколько PWA на одном origin](https://web.dev/articles/building-multiple-pwas-on-the-same-domain).

## 3. Границы хранения и резервной копии

CacheStorage хранит поставленные ресурсы, IndexedDB прогресса — пользовательские записи. Технический реестр PWA хранится отдельно от экспортируемого прогресса: `isketatar-pwa` содержит выбранные release IDs, имена кэшей, состояние полноты и незавершённую операцию обновления. Его потеря вызывает повторную проверку ресурсов, а не reset обучения. Worker не читает ответы, черновики или оценки.

Минимальная запись реестра: schema_version, current_release_id, previous_release_id|null, candidate_release_id|null, offline_requested, releases[] и operation|null. Элемент releases содержит release_id, manifest_url, manifest_sha256, shell_cache, course_cache, completeness, verified_at; operation — update_id, from_release_id, target_release_id и phase=prepared|committed. Digest готового manifest не включается в его собственный assets. Смена указателей и маркера — одна транзакция технической БД; marker связывает её с update_gate прогресса при восстановлении после сбоя.

В WebKit 17+ верхний ориентир квоты origin в браузере/standalone — до 60% диска, общий предел — до 80%; это не выделенный приложению объём. estimate приблизителен, любая запись может отказать. После осмысленного сохранения офлайн или прогресса допускается persist-запрос с обработкой отказа. У Home Screen web app есть исключение из определённой ITP-очистки, но пользовательская очистка, нехватка места и удаление данных всё равно возможны. [WebKit storage](https://webkit.org/blog/14403/updates-to-storage-policy/), [WebKit Tracking Prevention](https://webkit.org/tracking-prevention/), [MDN quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

Синхронизации между устройствами нет. В Safari установка не переносит IndexedDB/localStorage из браузера; копирование cookies при создании Mac web app не является переносом прогресса. Перед переходом в новую среду предлагается экспорт/импорт. Базовый механизм — Blob/download и input type=file; File System Access и системный Share только дополнительные возможности. Факт подготовки download не доказывает сохранение файла пользователем. Формат, пределы, preview и замена определены в 02/09. [MDN download](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/a#download), [file input](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file), [showSaveFilePicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker).

## 4. Полный офлайн-пакет

Обычная первая загрузка автоматически сохраняет только небольшую оболочку: HTML, стартовые JS/CSS, интерфейсный шрифт и recovery UI. Полный пакет сохраняется по явному «Интернетсыз уку өчен сакларга». Он включает все required assets выпуска: все маршруты и lazy chunks, уроки, задания, диагностику/итог, чтение, основной и учебный словарь, справочники, интерфейсные строки, sources/sections.json, шрифты Inter и Noto Naskh Arabic. Ключи статического курса доступны в JSON; ограничения показа действуют и офлайн.

Полный DOC, sources/textbook.txt, инструменты и аудиты не входят в dist. Аудио первого выпуска отсутствует; кнопок для него нет. Возможное будущее аудио получает отдельное явное скачивание и состояние полноты; частичное проигрывание не означает сохранение всего файла. Текстовый пакет не зависит от него.

| Состояние | Значение |
|---|---|
| not_saved | Полного подтверждённого пакета нет, даже если отдельный урок уже закэширован |
| downloading | Счётчик проверенных ресурсов/байтов; можно отменить |
| verifying | Проверяются обязательный список, размеры, хеши и структура |
| ready | Все обязательные ресурсы выбранного release доступны; показаны версия и время проверки |
| incomplete | После очистки или сбоя отсутствует часть ранее сохранённого пакета |
| failed | Причина загрузки/квоты/проверки и повтор; прежний рабочий пакет сохранён |

Загрузчик принимает только разрешённые GET по точным URL: успешный статус, ожидаемый MIME, конечный URL без неожиданного redirect, размер и SHA-256 по manifest. Opaque и HTML вместо JSON отвергаются. Частично скачанный пакет не становится current. После записи повторно проверяются наличие всего required списка и корректность каталога; лишь затем атомарно отмечается готовность в техническом реестре. CacheStorage и IndexedDB не образуют общей транзакции: незавершённая метка после сбоя пересчитывается, а не считается доказательством полноты.

Один кандидат загружается в собственные кэши выпуска; существующий пакет не перезаписывается. Байты сверх объявленных manifest limits отвергаются; бюджет полного выпуска задаётся приёмкой 10. При квоте удаляется отменённый staging, предлагается освободить место или отказаться от скачивания. Прогресс и закреплённый пакет не становятся неявными жертвами очистки.

При каждом старте статус ready сверяется с наличием required объектов; конкретный ресурс перед использованием проверяется по хешу, при несовпадении пакет становится incomplete. navigator.onLine служит подсказкой; только запрос подтверждает доступность хоста. Первый визит без сети и без оболочки невозможен. Полнота проверяется холодным перезапуском без сети, включая открытие ранее не посещённых уроков, словаря и шрифтов. [MDN onLine](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/onLine), [MDN caching](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching).

Шрифты поставляются локально по разрешённой лицензии, без внешней CSS/CDN зависимости. При потере Noto оцениваемая арабица приостанавливается по 04; кириллическая теория и восстановление доступны. Успешный fetch не доказывает корректное покрытие графики: глифы и shaping проходят отдельную типографическую приёмку.

## 5. Ограниченное хранение выпусков

Постоянные роли — **current** и максимум один **previous**. Previous означает предыдущий успешно принятый выпуск на этом устройстве: после долгого перерыва это может быть не серверный N−1. Допускается ещё один временный candidate. У каждого выпуска отдельные `isketatar-shell-<release_id>` и `isketatar-course-<release_id>`; максимальный суммарный объём ограничен суммой allowlist-байтов этих трёх выпусков. Перед загрузкой нового candidate освобождается прежний незанятый временный слот. При незавершённом согласовании вкладок новый install откладывается, сохраняя рабочий worker; четвёртый выпуск не скачивается.

Pin — ссылка active/paused Session на release_id. Представленный в открытой вкладке выпуск также занят до её готовности к переключению. Submitted/abandoned/incompatible не закрепляют полный пакет навсегда: исходные Attempts и версии сохраняются, а старый подробный разбор может требовать ещё доступного пакета. Без него показываются достоверные сохранённые результаты и объяснение недоступности подробностей, без подстановки современного ключа.

Правила перехода R2→R3 при current=R2, previous=R1:

1. Проверить новый reader: поддерживает ли он content_schema и все policy_versions каждого остающегося закреплённого выпуска. Совпадения ContentId или min_reader_version недостаточно. Неподдерживаемый сеанс сначала завершают в прежнем приложении либо явно оставляют как incompatible с черновиком и доступным экспортом. Для продолжаемого pin retained-пакет должен быть полным; недостающее скачивается до переключения с указанием общего размера. Старую JS-оболочку не запускают поверх новой БД: продолжение обеспечивает новый reader с явно проверенной поддержкой старой политики.
2. Если R1 ещё нужен незавершённому сеансу, обновление откладывается. В интерфейсе перечислены конкретные занятия: продолжить их либо явно оставить исторические черновики, которые новая версия не сможет продолжить. Автоматического restart нет.
3. После освобождения R1 и согласования вкладок R3 становится current, R2 — previous. Только теперь неиспользуемый R1 допускается удалить. При interrupted commit проверяются фактические роли и pins перед очисткой.
4. Previous хранится до следующего принятого обновления или отдельного удаления пользователем. Неполный staging старше 24 часов и готовый непринятый candidate старше 7 дней удаляются при следующем активном запуске, если операция не выполняется. Фоновый таймер не обещается.

Готовый candidate не является согласованием его установки. Для принятия обновления полный новый пакет скачивается только после явного действия «Саклап яңартырга» с указанным размером. Это позволяет сохранить обещанную офлайн-работу при переключении; человек вправе продолжить текущую версию без этой загрузки. Серверный artifact содержит текущий и предыдущий опубликованные пакеты; URL неизменяемы, но их вечная доступность не обещается. Удалённый на сервере старый пакет может оставаться в локальном previous, пока действует его pin.

Workbox не управляет этими ролями автоматически. Его обычная активация удаляет отсутствующие в precache manifest записи; поэтому используются отдельные имена кэшей выпуска и явный контроль очистки. Общая cleanupOutdatedCaches не должна затрагивать previous или чужой namespace. При смене формата Workbox совместимость сохранённых кэшей проверяется до выпуска. [Workbox precaching](https://developer.chrome.com/docs/workbox/modules/workbox-precaching).

## 6. Обновление всех вкладок

Service worker и принятие учебного выпуска имеют разные моменты жизни. Браузер может естественно активировать waiting worker после закрытия всех его клиентов. Поэтому событие activate само по себе не меняет current, не мигрирует прогресс и не удаляет previous. Новый transport worker умеет обслуживать сохранённый current по его manifest. skipWaiting не вызывается при install автоматически; clients.claim также не добавляется шаблонно. URL sw.js стабилен. [Жизненный цикл SW](https://web.dev/articles/service-worker-lifecycle).

Проверка обновления выполняется при запуске, явном действии и возвращении в приложение после длительного отсутствия; автоматическая проверка ограничена одним запросом за час. Ошибка сети не блокирует старый курс. До действия пользователя показывается предложение, без reload и изменения задания. Нет гарантированного Background Sync, ежедневной загрузки или автоматической резервной копии: запись ответа выполняется в активной странице. [MDN background operation](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Offline_and_background_operation).

Протокол принятия нового выпуска:

1. Координатором является действующий writer: он проверяет candidate и совместимость, сохраняя свой writer_epoch. Другая вкладка передаёт ему запрос обновления, не забирая право до flush его очереди. Неответивший writer блокирует обновление; отдельное явное recovery/takeover объясняет, что неподтверждённый ввод прежнего окна может не сохраниться, и только затем позволяет начать новое согласование. Создаёт update_gate={update_id,target_release_id,phase,coordinator_id,requested_at} в meta/control: UUID операции, целевой release, quiescing|commit, ID координатора и время. Gate не экспортируется, не заменяет writer_epoch и проверяется командами в транзакции. В quiescing запрещены новые занятия, import/reset и новое раскрытие помощи; разрешены завершение текущих draft, уже начатых монотонных записей показа/помощи и pause.
2. Через worker получается список window clients с includeUncontrolled=true, затем фильтруется точный origin и pathname внутри `/isketatar/`. Включены фоновые вкладки и установленные окна того же storage-контекста. Каждому отправляется prepare(update_id, target_release); ACK привязан к его client ID. BroadcastChannel ускоряет уведомление, но не заменяет ответы конкретных клиентов. [Clients.matchAll](https://developer.mozilla.org/en-US/docs/Web/API/Clients/matchAll).
3. Каждая страница блокирует новые действия, завершает composition/очередь записи, включая начатую помощь из любой вкладки, и запоминает навигацию. Владелец записи сохраняет ResumePosition и приостанавливает active; остальные вкладки держат позицию в своей истории. Только после transaction completion страница отвечает ready; ACK не передаёт чужой вкладке право pause или изменения черновика. Старые соединения БД закрываются; координатор закрывает своё после записи commit. Страница в режиме памяти требует явного решения о несохранённой работе; её нельзя молча перезагрузить. Неизвестная старая вкладка без протокола должна быть закрыта пользователем.
4. Ожидание одного раунда — 15 секунд. Отсутствие ответа не считается согласием или закрытием: показываются мешающие окна, «Повторить» и «Отложить». Закрытый клиент исключается лишь после нового matchAll. Перед commit список перечитывается; новый клиент проходит тот же prepare. Bootstrap новой страницы видит gate и не начинает записывающих команд.
5. В commit заморожены пользовательские команды записи, включая монотонную помощь; разрешены техническое завершение gate и согласованная миграция. Повторно проверены pins и revisions. Реестр PWA фиксирует переход current/previous и маркер операции. Если нужный worker ещё waiting, ему разрешается skipWaiting для согласованного update_id. При уже активном совместимом transport worker этот шаг пропускается. Если контролируемый worker действительно сменяется, страницы ожидают controllerchange. При уже активном совместимом worker проверяют его identity/регистрацию и переходят к согласованному reload, не ожидая нового controllerchange. Неконтролируемая страница также проверяет активный worker регистрации, не ждёт невозможного события. После подтверждения страницы перезагружаются ровно один раз с сохранением hash-маршрута. [skipWaiting](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/skipWaiting), [controllerchange](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerContainer/controllerchange_event).
6. Новый shell проверяет свою версию, реестр, схемы и пакет перед разрешением команд; успешный согласованный bootstrap завершает операцию снятием gate. Сеансы остаются paused до явного resume. Если координатор исчез или осталась оборванная операция, recovery заново получает состояние worker, реестра, кэшей и вкладок. Только явное действие координатора отменяет ожидание либо заново согласует продолжение; timeout, смена writer_epoch и старые ACK не снимают gate автоматически. Отмена до commit сохраняет прежний current. После состоявшегося переключения снятие блокировки не откатывает current, БД или уже записанную помощь.

Gate и реестр не делают несколько API одной транзакцией: явные фазы позволяют восстановиться после прекращения процесса на любой границе. Старые callbacks не получают новые writer/data-generation полномочия. Перед закрытием последней вкладки может остаться waiting worker, но следующий запуск всё равно проверяет принятый current. Hard reload, обошедший worker и принёсший другой shell, не разрешает запись до согласования версии. Протокол не распространяется между изолированными Safari/browser/installed хранилищами: каждая копия обновляется самостоятельно.

## 7. Удаление и восстановление

«Сакланган курсны бетерергә» удаляет только полный офлайн-пакет и временные загрузки; небольшая recovery-оболочка остаётся. Действие сначала сохраняет/приостанавливает занятие и объясняет, какие закреплённые выпуски потребуются для продолжения. Старая версия могла уже исчезнуть с сервера: до удаления не обещается её повторное скачивание. Подтверждение касается кэша, не Attempts, Session, настроек, закладок или data_generation.

Удаление координируется со всеми клиентами, чтобы соседняя вкладка не докачала пакет обратно. Сначала выключается готовность/намерение полного офлайна в реестре, затем удаляются только перечисленные собственные course-кэши и непринятый candidate. Ошибка удаления оставляет статус incomplete с повтором. Просмотр курса онлайн не включает полное автоматическое скачивание снова. Удаление всего browser site data — внешняя операция с иными последствиями; приложение не может сохранить IndexedDB вопреки ей.

Если браузер вытеснил пакет, но прогресс цел, незавершённый сеанс сначала пытается получить именно закреплённый совместимый release. Сетевая ошибка показывает content_unavailable и повтор. Постоянно недоступная/неподдерживаемая версия даёт исторический черновик, экспорт и новое начало; современный вопрос не подставляется под старый ID. При потере прогресса, но сохранённом курсе показывается новый локальный набор с возможностью импорта, без реконструкции оценок из кэша.

Откат хостинга является новым согласованным выпуском, а не откатом пользовательской БД. Предыдущая оболочка не запускается после миграции, которую она не умеет читать. Удаление сайта не отзывает уже скачанную копию у офлайн-устройства. Условия безопасного отката и проверки artifact определяет 10.

## 8. Приёмка

Обязательны: первая загрузка без worker; браузер без beforeinstallprompt; установка Safari с отдельным прогрессом; перенос файлом; отказ persist/QuotaExceededError; полный холодный офлайн-старт; потеря одного JSON/шрифта; неверный hash/MIME; отменённый staging; два окна и фоновая неответившая вкладка; новая вкладка между ACK и commit; сбой на каждой фазе переключения; естественная активация worker после закрытия всех окон; R1 pin при R2→R3; неподдерживаемая старая policy; удаление курса при сохранённых Attempts; импорт ссылки на исчезнувший release; смена origin. Это будущие проверки реализации, а не выполненные испытания.

На Pages опубликованный сайт ограничен 1 GB; трафик 100 GB/месяц — мягкий предел, публикация ограничена 10 минутами. Мягкий лимит 10 сборок/час не относится к custom Actions workflow. Бюджет артефакта включает два серверных выпуска и возможные будущие медиа; конкретный размер измеряется сборкой. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).
