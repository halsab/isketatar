# Взаимодействие, движение и доступность

Контракт будущей реализации, 12 сентября 2026 года. Дополняет [экраны](06-screen-specs.md), [маршрутизацию](05-routing.md) и [дизайн-систему](04-design-system.md). Учебные последствия действий определяет [механика](03-learning-mechanics.md), сохранение — [модель данных](02-data-contracts.md). Здесь фиксируются способы управления, переходы фокуса и условия проверки. Приложение, браузерные испытания и сертификация доступности этим документом не выполнены.

## 1. Общая модель управления

Любое обязательное действие доступно обычной кнопкой, ссылкой или полем и выполняется без точного жеста, наведения и ограничения времени. Предпочтительны нативные HTML-контролы. Настоящая ссылка сохраняет открытие новой вкладки, копирование адреса и браузерную историю. Кнопка не маскируется под ссылку. Вложенные интерактивные элементы и положительные tabindex исключены.

Страница имеет осмысленный title, один основной main, последовательные заголовки, подписанную навигацию и видимую при фокусе ссылку пропуска к содержимому. Порядок DOM соответствует чтению; CSS не переставляет controls относительно их клавиатурного порядка. Статус текущего раздела передаётся aria-current. Подпись и доступное имя совпадают по смыслу: видимое татарское название входит в имя, что поддерживает голосовое управление. Основание — [WCAG 2.5.3](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html).

Наведение и фокус сами не выбирают ответ, не открывают подсказку и не запускают сеанс. Изменение radio/checkbox сохраняет выбор, но не оценивает его. Проверка требует отдельной команды. Важные предупреждения остаются рядом с действием; единственное исчезающее уведомление не считается объяснением ошибки.

## 2. Клавиатура и текстовый ввод

| Контекст | Управление |
|---|---|
| Общий порядок | Tab и Shift+Tab обходят доступные controls; браузерные сочетания сохраняются |
| Кнопка | Enter/Space активируют нативно; повтор события не дублирует команду |
| Ссылка | Enter открывает; модификаторы браузера не перехватываются |
| Radio | Стрелки меняют выбор внутри группы; не отправляют ответ |
| Checkbox | Space меняет признак; Tab переходит к следующему |
| Обычный reading/segment | Enter вне composition вызывает «Тикшерергә», только если это текущая допустимая команда |
| Диагностика и итог | Ввод меняет черновик; Enter в поле не отправляет весь сеанс |
| Поиск | Enter завершает debounce и подтверждает текущий запрос |
| Escape | Закрывает ближайшие локальные предложения, затем активную панель/диалог; не стирает ответ |

Нет глобальных односимвольных сочетаний, конфликтующих с татарским вводом или командами скринридера. Стрелки, Home/End, выделение, Ctrl/Cmd+A/C/V/X/Z и системное редактирование остаются нативными в поле. Не назначать Enter одновременно обработчику поля и формы так, чтобы возникали две отправки. Требование работы без специального ритма нажатий основано на [WCAG 2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html).

Поле ответа — однострочное LTR-поле кириллицы с постоянной подписью. Подсказка формата связана через aria-describedby. Пустота, недопустимый размер и ошибочный формат сообщаются возле поля; локальная проверка формата не раскрывает правильность учебного ответа. Browser spellcheck, автокоррекция и автоматическая капитализация для оцениваемого ввода отключаются, насколько это поддерживается платформой; приложение дополнительно не исправляет текст. Вставка разрешена. Исходное значение сохраняется отдельно от нормализованного сравнения.

### Шесть татарских клавиш

`ә ө ү җ ң һ` и отдельный `+` для segment — обычные подписанные кнопки. Вставка заменяет выбранный диапазон **целевого поля**, а не всегда дописывает в конец. Сохраняются selectionStart, selectionEnd и направление выделения; после вставки курсор находится после вставленного символа. Позиция берётся из нативного диапазона UTF-16, не вычисляется по видимым столбцам, RTL-положению или длине нормализованного ответа.

Нажатие указателем не должно терять запомненный диапазон из-за перемещения фокуса на кнопку. Клавиатурная активация кнопки использует последнее корректное выделение связанного поля и возвращает туда фокус. Команда не меняет другое поле, если экран или предъявление уже сменились. Одна активация означает одно редактирование диапазона через стандартный API поля. Нативное undo для программной вставки проверяется на целевых браузерах и не предполагается автоматически; deprecated execCommand не является обязательной зависимостью. Где платформа не включает такую вставку в undo, сразу доступна отдельная «Кертүне кире кайтарырга»: она восстанавливает значение и диапазон до последней виртуальной вставки только пока значение поля совпадает с её результатом. Последующее редактирование/смена вопроса отменяет эту возможность. Собственную общую историю редактирования и глобальный перехват Cmd/Ctrl+Z не вводить; нативное редактирование системной клавиатуры сохраняется.

Во время IME composition Enter не проверяет ответ, состояние composition не сбрасывается рендером. Виртуальная клавиша не вмешивается в незавершённую композицию: операция не выполняется и не ставится скрыто в очередь; доступное пояснение предлагает завершить текущий ввод. После compositionend работает обычная вставка. Нельзя очищать поле по blur или считать потерю фокуса отправкой.

Изменение текста сохраняет черновик по принятому контракту. Индикатор записи не обещает durable save до commit. При ошибке прежнее значение остаётся видимым; работа в памяти сопровождается постоянной отметкой. Возврат на paused review восстанавливает его фиксированный план, а не генерирует новую очередь из текущих due.

## 3. Нажатие, жесты и выделение

Визуальная реакция начинается на pointerdown; предметное действие выполняется при обычной активации на отпускании. Уход указателя с цели, начало прокрутки и pointercancel отменяют нажатие без открытия помощи, вставки буквы или submit. Не добавлять отдельный touchend поверх click. Клавиатурная и ассистивная активация проходят через ту же команду. Это выбранная реализация отмены по [WCAG 2.5.2](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html).

В v1 нет обязательного свайпа карточки, перетаскивания морфем или жеста закрытия панели. «Алга», выбор части, закрытие и возврат имеют видимые controls. Нативная прокрутка не заменяется собственным инерционным движком. Pinch zoom, системные краевые Back-жесты, выделение долгим нажатием и жесты скринридера не перехватываются. Не задавать touch-action:none на странице, чтении или поле. Не блокировать контекстное меню текста.

Слова читалки остаются непрерывным выделяемым текстом. Протягивание для выделения и завершение прокрутки не открывают словарь. Наличие выделения не очищается ради обработки click. Активация слова допускается после обычного короткого нажатия без отмены и изменения выделенного диапазона; синтетический click после отменённого жеста игнорируется.

Клавиатурный эквивалент доступен у строки через подписанное действие «Сүз сайларга»: оно раскрывает в потоке под строкой выбор точного вхождения по видимому написанию и порядку, без чтения/значения. Элементы выбора — обычные кнопки; нового модального слоя или маршрута нет. Это не требует превращать каждую арабскую букву в control или проходить весь текст десятками обязательных Tab. Само открытие выбора не является раскрытием разбора. После выбора панель сначала содержит форму и кнопки помощи; каждый уровень раскрывается явно.

Интерактивные слова внутри обычной строки сохраняют естественную геометрию; их области не расширяются поверх соседних слов. Отдельные кнопки имеют проектные размеры 44–48 px. У [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) минимум AA — 24 × 24 CSS px с предусмотренными исключениями, включая встроенные в текст цели; это не универсальное требование 44 px. Если позже появляется drag, ему нужна альтернатива простыми нажатиями по [2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html).

## 4. Фокус и переходы

Фокус виден целиком: контур 3 px, непрозрачный зазор 2 px, цвета из токенов. Его не обрезает overflow контейнера; sticky-элементы и экранная клавиатура не перекрывают цель. При недостатке высоты закреплённое действие переходит в поток. Прокрутка к фокусу учитывает фактическую шапку, без постоянного возврата к старому scrollY.

| Событие | Куда переходит фокус |
|---|---|
| Полный переход на страницу | Заголовок нового основного содержимого; title обновлён |
| Переход по явному `at` | Смысловой блок/его заголовок, с сохранённым возвратом |
| Back/Forward | Сохранённая цель при её существовании; иначе заголовок восстановленного блока |
| Фильтр, набор поиска, раскрытие модуля | Остаётся на текущем control |
| Локальная ошибка поля | На поле, с описанием ошибки |
| Submit обычного вопроса | После принятого результата — заголовок feedback |
| Явное «Алга» после feedback | Заголовок следующего вопроса; acknowledgement записывается отдельно |
| Следующий шаг диагностики/итога | Заголовок вопроса без оглашения correctness |
| Раскрытие встроенной подсказки в потоке вопроса | На инициаторе; новый блок доступен следующим по порядку. Для word/rule/source-панели действует перенос фокуса по §5 |
| Завершение сеанса | Заголовок результата после фиксации сеанса |

Фокусируемый заголовок использует временный/программный tabindex=-1 и не добавляет лишнюю остановку Tab. При обновлении счётчика, фоновой записи и загрузке шрифта фокус не перехватывается. Не ставить его автоматически в поле при входе с телефона: это неожиданно открывает клавиатуру и скрывает условие. Пользователь сначала получает контекст вопроса.

Во время submit контроль остаётся на месте; повторная команда блокируется предметной идемпотентностью и состоянием недоступности без исчезновения фокуса. Быстрый повтор Enter не активирует «Алга» после смены экрана. Никакой переход фокуса не служит сам по себе отправкой, просмотром feedback или доказательством прочтения.

Минимум [WCAG 2.4.11 AA](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) запрещает полное перекрытие цели авторским содержимым; проект требует видимости всей цели. [2.4.13 Focus Appearance](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html) относится к AAA. Контур 3 px не является автоматическим заявлением выполнения AAA: площадь индикатора и изменение контраста состояний проверяются отдельно.

## 5. Панели, диалоги и смена ширины

В каждый момент открыта одна контекстная панель. На узком и среднем окне она модальна: имеет имя от видимого заголовка, корректную dialog-семантику и aria-modal=true; фон inert, недоступен Tab и скринридеру. Фоновая прокрутка заблокирована с сохранением позиции. Tab/Shift+Tab остаются внутри; Escape и видимая кнопка закрывают. У структурированной длинной статьи начальный фокус получает заголовок, а не последний доступный control. Не передавать всю статью одной строкой aria-describedby. Основание — [WAI-ARIA APG Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).

На широком окне соседняя панель немодальна: без aria-modal, inert и ловушки Tab. Это именованный немодальный dialog. Нативный dialog сохраняет допустимую HTML/ARIA-семантику и тот же DOM при resize; подмена его role на region недопустима. После явного открытия фокус переходит к её заголовку, затем доступны controls и выход к тексту. Замена слова обновляет ту же панель. При её закрытии возвращается исходное слово/кнопка выбора; исчезнувшая цель заменяется заголовком соответствующей строки или основного блока.

При переходе через 1120 px адрес, word_id, раскрытая помощь и внутренний scroll сохраняются. Узкая→широкая: снимаются inert и блокировка, фокус остаётся на том же control панели. Широкая→узкая: если фокус уже внутри, он сохраняется; если снаружи, переходит на заголовок новой модальной области. Семантика и блокировка меняются согласованно, без кадра с фокусом в скрытом фоне. Resize не закрывает панель и не создаёт history item.

Ссылка на полную статью или источник снимает блокировку и выполняет обычный переход по 05. Back восстанавливает панель и её последнюю цель фокуса. Прямой URL панели без известного инициатора закрывается безопасным переходом к основной странице; фокус получает её заголовок.

Подтверждение помощи, импорта или reset не накладывается вторым модальным диалогом. Текущая панель временно уступает единственный слой, сохранив контекст; отмена возвращает его. В подтверждении необратимой замены/удаления начальный фокус стоит на отмене. Escape до commit отменяет намерение, после начавшегося атомарного commit не обещает откат. Результат операции остаётся доступным, даже если анимация закрытия отменена.

## 6. Оглашение состояния и границы помощи

Короткий status с polite-оглашением используется для числа найденных групп, готовности пакета, смены режима и успешной записи по явному действию. Всё содержимое страницы не помещается в aria-live. Поиск объявляет итог после принятого debounce 250 мс; устаревший запрос не меняет новый счётчик. Повторная запись каждого символа не создаёт голосовой поток. Эти события относятся к [WCAG 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html).

Feedback, получивший фокус, не дублируется вторым полным live-объявлением. Inline-ошибка связывается с полем и aria-invalid; alert допустим для новой ошибки, требующей немедленного внимания, например потери возможности сохранять. Текст ошибки остаётся на странице. Обычный incorrect не превращается в тревожное системное сообщение. Загрузка обозначает занятость только соответствующего региона, не скрывает целиком доступную навигацию.

Закрытый ответ отсутствует в DOM, доступном дереве, aria-label/description, title и скрытой инструкции. Стимул остаётся настоящим текстом с правильным языком; его не удаляют из accessibility tree для сохранения сложности. После разрешённого раскрытия значение доступно всем способам управления. Политика помощи не меняется для скринридера.

До submit диагностики/итога доступны только ответ, unknown и навигация; hints, reveal, правило и словарь внутри задания отсутствуют. Выход к учебному материалу, включая выдачу с чтениями, сначала учитывает все незавершённые проверки. Отмена предупреждения не раскрывает материал даже через live region. В обычном чтении каждая ступень помощи записывается до её показа; скрытие блока и переключение режима не восстанавливают самостоятельность.

## 7. Арабографика, язык и готовность шрифта

Основной язык — tt-Cyrl; татарская арабица — tt-Arab с RTL-изоляцией. Кириллическое поле, числа и внешние ссылки не наследуют направление всей арабской строки. DOM хранит логический порядок, word_id относится к точному вхождению. При выделении и копировании сохраняются ZWJ/ZWNJ и marks. Ни обработчик указателя, ни доступное имя не запускают NFKC или замену исторической формы.

Набор не разрывается обёртками внутри соединяемого слова. Рамки, выделение и фокус относятся к контейнеру, не растягивают глифы. Диапазоны слов проверяются по текущей ревизии, без разрезания составной последовательности. Вся матрица [типографических случаев](typography-fixtures.json) применяется также к открытой панели, выделению и состоянию ответа.

Перед оцениваемым стимулом загружается ожидаемый Noto Naskh Arabic face и проверяется его готовность. Один FontFaceSet.check не доказывает использование нужного семейства: результат сопоставляется с реально загруженным ожидаемым face через load и статусом файла. [CSS Font Loading](https://www.w3.org/TR/css-font-loading-3/) задаёт API, а сравнение начертаний остаётся проверкой проекта. При сбое показана татарская причина и восстановление; черновик остаётся paused, fallback не оценивается. Кириллическая теория доступна.

Языковая разметка не обещает наличие татарского голоса и нормативное историческое произношение. Доступное имя не дополняется кириллическим ключом, скрытым от зрячего ученика. Для заданий на зрительное различение начертаний эквивалентность альтернативного способа проверки требует отдельного предметного решения; доступность controls сама её не доказывает. Язык частей задаётся по содержанию, а не предположению об арабском голосе: [WCAG 3.1.2](https://www.w3.org/WAI/WCAG22/Understanding/language-of-parts.html).

## 8. Движение и прерывание

Все численные значения берутся из [design-tokens.json](design-tokens.json). Перенос величин в отдельные несовместимые константы не допускается.

| Токен | Значение | Применение |
|---|---|---|
| press | 120 мс | Реакция оболочки кнопки |
| press_scale | 0.98 | Оболочка кнопки действия; не поле и не арабский стимул |
| feedback | 160 мс | Появление блока результата |
| panel / panel_distance | 200 мс / 16 px | Открытие и закрытие панели |
| dialog / dialog_distance | 240 мс / 12 px | Открытие и закрытие диалога |
| route_fade | 120 мс | Допустимое краткое появление новой страницы |
| ease_out | cubic-bezier(0.2, 0, 0, 1) | Появление и переход к конечному состоянию |
| ease_in | cubic-bezier(0.4, 0, 1, 1) | Закрытие |
| reduced | 0 мс | Все переходы при reduce |

Арабский стимул, текстовый ответ и слово для выделения не масштабируются от нажатия. Панель входит и выходит по одному пути; у соседней колонки смещение по горизонтали, у диалога по вертикали. Это короткие переходы, без пружин, отскока, параллакса и непрерывного декоративного движения. Не анимировать высоту текста или прокрутку при каждом вводе; прозрачность и transform не меняют финальную геометрию.

Новое открытие/закрытие прерывает текущее движение и начинается из фактически видимого положения. Устаревший callback не удаляет уже повторно открытую панель, не возвращает фокус на старый экран и не выполняет учебную команду. Выбор другого слова не проигрывает заново весь вход панели. Ввод остаётся доступным во время перехода; временная блокировка возможна из-за атомарной записи, не ради красоты анимации.

Состояние, помощь и запись результата фиксируются независимо от animationend/transitionend. Уход со страницы отменяет её движение и отложенные визуальные callbacks. Восстановление после фоновой вкладки сразу показывает актуальное состояние без очереди старых эффектов. Результат показывается после принятого сохранённого либо явно несохранённого снимка, без искусственной задержки.

Settings=reduce или системный prefers-reduced-motion при Settings=system немедленно дают длительность 0, убирают translate/scale и плавную прокрутку. Смена предпочтения во время движения завершает его в актуальном состоянии и отменяет остаток. Текстовые статусы, фокус и результат сохраняются; ожидание события конца анимации не требуется. Тема и изменение размера текста применяются без анимации страницы и без сдвига смыслового якоря.

Арабицу не разряжают искусственно ради механического теста.

Аудио/видео в v1 отсутствуют; появление записей потребует отдельной проверки медиа-критериев.

## 10. Практическая приёмка

Для каждой строки матрицы фиксируются фактические ОС, браузер, версия ассистивной технологии, пакет содержания и результат. Версии не подменяются словами «последний браузер». Автоматическая проверка дополняет ручную и не подтверждает произношение, фокус или качество начертаний самостоятельно.

| Среда / сценарий | Обязательный результат |
|---|---|
| Только клавиатура: курс → вопрос → feedback → чтение → словарь | Все действия доступны; нет ловушки; известен текущий вопрос и возврат |
| VoiceOver + Safari, iPhone/iPad | Touch exploration, выбор слова, модальная панель, клавиатура и возврат работают без утечки ключа |
| VoiceOver + Safari, macOS | Заголовки, landmarks, controls и полная статья читаются в правильном порядке |
| TalkBack + Chrome, Android | Выбор ответа, TT-клавиши, объявления ошибки и закрытие панели сохраняют контекст |
| NVDA + Firefox и Chrome, Windows | Browse/forms mode, radio/checkbox, поля, live regions и возврат из диалога согласованы |
| 320/360/640/1120 px; обе ориентации | Меню/навигация и модальность меняются без потери слова, draft и фокуса |
| 200% текста; 400% desktop zoom до 320 CSS px; все размеры арабицы | Нет скрытых действий, обрезанных marks и горизонтальной прокрутки страницы |
| Увеличенные интервалы; forced-colors; обе темы | Содержание и состояния различимы; контур и подписи остаются видимыми |
| IME, выделение середины ответа, вставка, undo, TT-кнопки | Один ожидаемый edit; нет потери диапазона, composition или самовольного submit |
| Долгое нажатие, протягивание, pointercancel, pinch, край экрана | Системный жест сохранён; помощь и ответ случайно не активированы |
| Resize при открытой панели и focused control | Единственный слой, правильная модальность, та же цель и отсутствие скрытого фокуса |
| Reduce включён до/во время движения; быстрое открытие/закрытие | Нулевая длительность либо корректное прерывание; нет старого callback |

Отдельно проверяется доступное дерево до/после reveal и итогового submit: отсутствие ключа до допуска, доступность разбора после него. Любая потеря ответа, невозможность закрыть слой, скрытый фокус, недоступная основная команда или оценивание непроверенной арабицы блокирует соответствующий сценарий выпуска. Порядок выполнения и фиксации результатов уточняется планом качества.
